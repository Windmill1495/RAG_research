# QReCC 实验指南

三个实验统一使用 **混合检索（`hybrid`）**。BM25 按词项匹配排序，`bge-m3` 按向量相似度排序，最后用 RRF 融合两路排名。前两个实验用段落检索指标评估 Query，主实验同时评估独立问题的重写质量及其下游检索效果。三个实验都使用数据里已有的对话历史，默认最多保留最近三轮问答。

| 实验 | 对照内容 | 主要指标 |
| --- | --- | --- |
| 实验一 · Query 构造 | `current`、`history`、`rewrite`。
`rewrite` 使用 Qwen3-1.7B | Gold Recall@1、Gold Recall@3、MRR@3、Query 构造耗时、查询总耗时、错误数、回退数 |
| 实验二 · 模型规模 | 固定 `rewrite`，比较 Qwen3-1.7B、4B、8B、14B、32B | 沿用实验一的指标 |
| 主实验 · 重写方法 | 固定 Qwen3-8B。A 为直接重写，B 为结构化重写，C 待定 | 人工盲评合格率、ROUGE-1 F1、重写耗时、模型调用次数、错误数、回退数，以及下游 Gold Recall@1、Gold Recall@3、MRR@3 |

在项目根目录打开 PowerShell，确认 Ollama 已启动，先安装重写模型和向量模型。首次运行混合检索会计算语料向量，后续可复用同一语料与配置的索引。

```powershell
ollama pull qwen3:1.7b
ollama pull bge-m3
$py = 'G:\Anaconda3\python.exe'
```

换电脑时，把 `$py` 改为实际的 Python 路径，或在 Python 已加入 PATH 时写成 `$py = 'python'`。

## 实验一 · 比较三种 Query 构造方式

| 策略 | 怎样构造用于检索的 Query |
| --- | --- |
| `current` | 直接使用当前问题 |
| `history` | 按顺序拼接窗口内的历史问答和当前问题 |
| `rewrite` | 用 `qwen3:1.7b` 将追问重写成独立问题 |

三组共用相同的题目、历史窗口、混合索引和融合参数。每题取一次 Top-3，由同一排名计算 @1 和 @3。正式目标是在官方完整语料上检索。项目已有的官方测试 JSON 包含 16,451 轮，其中 8,282 轮有段落标注，6,915 轮同时有标注和历史。正式跑前核对索引与标注的 ID，报告实际计分题数和排除原因。建议同时报告全部有标注轮次和有历史的子集。未标注轮次不计入 Gold 指标的分母。 [QReCC 官方数据归档](https://zenodo.org/records/5760304)

### 指标怎么算

| 指标 | 计算方法 |
| --- | --- |
| Gold Recall@1、Gold Recall@3 | 取前 1 或前 3 名，计算命中的不同标注段落数除以该题标注段落总数，再按题平均。例如一题有两个标注段落，第一名命中其中一个，Recall@1 为 0.5。 |
| MRR@3 | 取前三名中第一个标注段落的名次倒数，未命中记 0，再按题平均。 |
| Query 构造耗时 | `latencies_ms.rewrite`。`current` 和 `history` 只计本地处理，`rewrite` 还包含模型调用。 |
| 查询总耗时 | `latencies_ms.total`。从构造 Query 到返回检索结果，不含索引构建、指标计算和答案生成。以毫秒报告均值，比较时统一预热。 |
| 错误数、回退数 | 分别查看 `error_count`、`rewrite_error_count` 和 `fallback_count`。硬失败保留在固定样本分母内，检索指标记 0。重写回退后仍检索的题按实际返回排名评分，同时单列回退次数。 |

### 现在怎么运行

```powershell
& $py -X utf8 -B evaluate.py --mode ollama --model qwen3:1.7b --strategies current history rewrite --split all --backend hybrid --top-k 3 --retrieval-only --output-dir outputs/runs/exp1_hybrid_307
```

这条命令运行项目的 **307 题和 9,975 段语料**。`summary.csv` 的 `gold_recall_at_1`、`gold_recall_at_3` 和 `mrr_at_3` 来自同一次检索。首次可加 `--limit 2` 并使用新的输出目录试跑。离线流程检查可改用 `--mode demo --backend bm25`，正式实验请使用混合检索命令。

正式全量检索还需为约 5,400 万段语料准备 BM25 索引和向量索引，并适配官方测试题与段落标注。现有 `evaluate.py --data` 读取项目格式的评估题。307 题结果应按项目小语料范围报告。 [项目检索入口](../evaluate.py) · [QReCC 作者的索引说明](https://github.com/apple-aiml-research/ml-qrecc/blob/main/collection/README.md)

## 实验二 · 固定 `rewrite`，比较五个模型

结果表每个模型一行，沿用实验一的全部检索与耗时指标。两次实验使用同一批题、同一索引、相同提示和历史窗口。五个模型统一思考模式、量化档位、生成参数、计时硬件和并发设置，并记录具体模型标签及权重摘要。在完全相同的设置下，可以复用实验一的 1.7B `rewrite` 行。

当前可用同一批 307 题比较已安装的模型。下面以 4B 为例。更换模型时只改 `--model` 与输出目录，保持 `bge-m3` 和混合索引一致。全量对照与实验一共用将来接入的完整混合索引。

```powershell
& $py -X utf8 -B evaluate.py --mode ollama --model qwen3:4b-q4_K_M --strategies rewrite --split all --backend hybrid --top-k 3 --retrieval-only --output-dir outputs/runs/exp2_hybrid_4b_307
```

先用 `ollama list` 确认实际安装的标签。为统一版本和量化，可选择原版 Qwen3 的 `q4_K_M` 标签并记录权重摘要。 [Ollama 模型标签](https://ollama.com/library/qwen3/tags) · [模型请求设置](../rag/llm.py)

## 主实验 · 固定 Qwen3-8B，比较重写方法

| 组别 | 当前设置 |
| --- | --- |
| A · `rewrite` | 直接生成一条独立问题 |
| B · `structured` | 先生成结构化结果，校验发现问题时尝试一次修复，再取最终改写 |
| C | 改进方向待定，当前运行 A/B 基线 |

给两组相同的追问和历史，最终输出与当前轮人工 `Rewrite` 比较。**人工盲评合格率**看改写能否独立理解、是否正确补全指代和省略、是否保留原意及时间、数量、否定等约束，以及是否加入无依据的信息。**ROUGE-1 F1**衡量词面重合，等义改写可以通过人工评审。另报重写耗时、模型调用次数、错误数和回退数，耗时包含 B 的条件修复。

对有段落标注且在索引里有证据的题，把 A/B 最终 Query 交给同一个混合检索器。下游指标使用实验一的 Gold Recall@1、Gold Recall@3 和 MRR@3。另看 `retrieval_sample_count`（检索计分题数）、`retrieval_error_count`（检索错误数）、`mean_retrieval_ms`（平均检索耗时）和 `mean_query_total_ms`（平均重写加检索耗时）。重写质量和下游检索分开看。

先用 `ollama list` 核对 8B 标签，如需安装可运行 `ollama pull qwen3:8b`。沿用前面的 `$py`，从同一批开发题试跑 A/B。

```powershell
& $py -X utf8 -B evaluate_rewrite.py --mode ollama --model qwen3:8b --strategies rewrite structured --split dev --limit 2
```

去掉 `--limit 2` 可跑 102 道项目开发题。固定方法后，可用 `--split test` 跑 205 道项目测试题。若只想在官方测试文件上评估改写质量，可加 `--rewrite-only`。

```powershell
& $py -X utf8 -B evaluate_rewrite.py --mode ollama --model qwen3:8b --strategies rewrite structured --data data/qrecc/source/qrecc-test.json --data-format qrecc-json --split test --rewrite-only
```

官方文件的 16,451 轮中有 13,676 轮带历史。当前脚本也会处理没有历史的首轮，分析重写质量时可按逐题记录里的 `history` 单独汇总有历史的样本。需要在本地小索引上做官方数据的检索诊断时，可改用 `--allow-partial-corpus`，并通过 `report.json` 的 `metadata.retrieval` 核对索引范围和标注覆盖。没有索引覆盖的题只参与重写评分。人工盲评应从正式报告的目标样本中固定抽题并独立评分。项目 307 题来自官方测试集，已经用来设计方法的会话应在独立验证时排除并注明。

## 输出文件和续跑

- 检索结果默认写到 `outputs/runs/`，重写质量结果默认写到 `outputs/rewrite_runs/`。先看 `summary.csv`，再按题目 ID 在 `report.json` 或 `details.csv` 中查 Query、改写来源、排名或错误。
- 主实验同时生成 `blind_review_reviewer1.csv` 和 `blind_review_reviewer2.csv`。两人独立打分后，再用 `blind_review_key.json` 对应回组别。更多操作见 [问题重写实验说明](问题重写实验说明.md)。
- 中断后可用原来的 `--output-dir` 和相同参数追加 `--resume`。另起一轮或换模型时使用新的输出目录。
