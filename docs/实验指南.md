# QReCC 实验指南

真实模型模式下，三个实验的下游检索统一使用 **混合检索（`hybrid`）**。BM25 按词项匹配排序，`bge-m3` 按向量相似度排序，最后用 RRF 融合两路排名。各组共用相同的历史窗口，QReCC 默认最多保留此前最近 3 个用户轮次。

| 实验 | 对照内容 | 主要指标 |
| --- | --- | --- |
| 实验一 · Query 构造 | 比较 `current`、`history`、`rewrite`，其中 `rewrite` 使用 Qwen3-1.7B | Gold Recall@1、Gold Recall@3、MRR@3、Query 构造耗时、查询总耗时、错误数、回退数 |
| 实验二 · 模型规模 | 固定 `rewrite`，比较 Qwen3-1.7B、4B、8B、14B、32B | 沿用实验一的指标 |
| 主实验 · 重写方法 | 固定 Qwen3-8B，比较 A 直接重写、B 结构化重写与 C CompCQR | 人工盲评合格率、ROUGE-1 F1、重写耗时、模型调用次数、错误数、回退数，以及下游 Gold Recall@1、Gold Recall@3、MRR@3 |

## 运行准备与数据范围

在项目根目录打开 PowerShell。使用真实模型前，启动 Ollama 并用 `ollama list` 检查所需模型。缺少默认模型时可执行下面的安装命令。

```powershell
$py = 'G:\Anaconda3\python.exe'
ollama pull qwen3:1.7b
ollama pull bge-m3
```

首次运行混合检索会计算语料向量，进度可在终端查看。语料、向量权重和索引配置一致时可复用 `.cache/qrecc/index.json`。离线 `demo` 用规则重写和 BM25 检查流程，BM25 另用 `.cache/qrecc/index-bm25.json`。`evaluate_rewrite.py --rewrite-only` 只评分改写文本，跳过索引和检索。首次启动和小样本验证见 [快速上手](快速上手.md)。

| 数据范围 | 当前怎样运行 |
| --- | --- |
| 项目子集 | 307 道追问，含 102 道开发题和 205 道测试题。下游检索使用本地 9,975 个段落 |
| 官方测试对话的重写质量 | 可用内置 `data/qrecc/source/qrecc-test.json` 和 `--rewrite-only`。文件有 16,451 轮，其中 13,676 轮有历史 |
| 官方全量语料的检索 | 后续需构建约 5,400 万段语料的索引，并适配官方测试题与段落标注。目前可以用本地索引做覆盖诊断 |

内置 307 题是依据本地段落覆盖筛选的追问，dev/test 划分与历史构造见 [数据来源说明](../data/qrecc/DATA_SOURCES.md)。正式报告应注明固定参考历史、数据划分和索引范围。若要在独立样本上验证方法，先将已用于设计或调参的会话划入开发或诊断集合。

## 实验一 · 比较三种 Query 构造方式

| 策略 | 怎样构造用于检索的 Query |
| --- | --- |
| `current` | 直接使用当前问题 |
| `history` | 按顺序拼接窗口内的历史问答和当前问题 |
| `rewrite` | 用 `qwen3:1.7b` 将追问重写成独立问题 |

三组共用相同的题目、历史窗口、混合索引和融合参数。每题取一次 Top-3，由同一排名计算 @1 和 @3。

### 指标怎么算

| 指标 | 计算方法 |
| --- | --- |
| Gold Recall@1、Gold Recall@3 | 取前 1 或前 3 名，计算命中的不同正例 ID 数除以该题 `positive_ids` 中不同正例 ID 总数，再按题平均。一题有两个标注段落且首位命中其中一个时，Recall@1 为 0.5。 |
| MRR@3 | 取前三名中第一个标注段落的名次倒数，未命中记 0，再按题平均。 |
| Query 构造耗时 | `latencies_ms.rewrite`。`current` 和 `history` 只计本地处理，`rewrite` 还包含模型调用。 |
| 查询总耗时 | 在 `--retrieval-only` 下，`latencies_ms.total` 从构造 Query 到返回检索结果。计时范围独立于索引构建与指标计算，比较时统一预热，单位为毫秒。 |
| 错误数、回退数 | 分别查看 `retrieval_error_count`、`rewrite_error_count` 和 `fallback_count`。检索硬失败记 0，并保留在固定样本分母内。重写回退后按实际检索排名计分，同时单列回退次数。 |

### 在项目子集运行

先试跑两道开发题的离线流程。真实模型的小样本试跑可在后面的混合检索命令中加入 `--limit 2`，并使用单独的输出目录。

```powershell
& $py -X utf8 -B evaluate.py --mode demo --backend bm25 --strategies current history rewrite --split dev --top-k 3 --limit 2
```

```powershell
& $py -X utf8 -B evaluate.py --mode ollama --model qwen3:1.7b --strategies current history rewrite --split all --backend hybrid --top-k 3 --retrieval-only --output-dir outputs/runs/exp1_hybrid_307
```

混合检索命令覆盖项目的 307 道题。`summary.csv` 的 `gold_recall_at_1`、`gold_recall_at_3` 和 `mrr_at_3` 来自同一次检索。只需评测开发题或测试题时，分别使用 `--split dev` 或 `--split test`。如果另外评测回答，把 `--retrieval-only` 换成 `--generate`，并用新的输出目录。

### 扩展到官方全量检索

全量对照要准备完整语料的索引，并把官方测试题和段落标注适配成 `evaluate.py --data` 支持的项目评测格式。内置官方测试 JSON 有   8,282 轮携带段落标注，其中 6,915 轮同时有历史。评测时核对段落 ID，报告实际计分题数及排除原因，并把有历史追问的结果单独汇总。 [项目检索入口](../evaluate.py) · [QReCC 作者的索引说明](https://github.com/apple-aiml-research/ml-qrecc/blob/main/collection/README.md)

## 实验二 · 固定 `rewrite`，比较五个模型

结果表每个模型一行，沿用实验一的全部检索与耗时指标。两次实验使用同一批题、同一索引、相同提示和历史窗口。五个模型统一思考模式、量化档位、生成参数、计时硬件和并发设置，并记录具体模型标签及权重摘要。在完全相同的设置下，可以复用实验一的 1.7B `rewrite` 行。

当前可用同一批 307 题比较已安装的模型。下面以 4B 为例。更换模型时只改 `--model` 与输出目录，保持 `bge-m3` 和混合索引一致。全量对照与实验一共用将来接入的完整混合索引。

```powershell
& $py -X utf8 -B evaluate.py --mode ollama --model qwen3:4b-q4_K_M --strategies rewrite --split all --backend hybrid --top-k 3 --retrieval-only --output-dir outputs/runs/exp2_hybrid_4b_307
```

先用 `ollama list` 确认实际安装的标签。为统一版本和量化，可选择原版 Qwen3 的 `q4_K_M` 标签并记录权重摘要。 [Ollama 模型标签](https://ollama.com/library/qwen3/tags) · [模型请求设置](../rag/llm.py)

## 主实验 · 固定 Qwen3-8B，比较重写方法

| 组别 | 当前设置 |
| --- | --- |
| A · `rewrite` | 直接生成一条独立问题 |
| B · `structured` | 先生成结构化结果，校验发现问题时尝试一次修复，再取最终改写 |
| C · `compcqr` | 两次模型生成组件，组合多查询检索并 RRF 融合，再用一次模型选择最佳段落 |

给三组相同的追问和历史。A/B 最终独立改写与当前轮人工 `Rewrite` 比较，C 只对其基础改写 `mq` 做这项比较，报告中标明 `base_rewrite_only`。**ROUGE-1 F1** 衡量词面重合。程序导出盲评表，由评审检查能否独立理解、是否补全指代和省略、是否保留原意及约束，以及是否加入无依据的信息，再计算**人工盲评合格率**。等义表达可以通过人工评审。另报重写耗时、模型调用次数、错误数和回退数，耗时包含 B 的条件修复。C 另记录组件生成、检索、融合、选择及总耗时和实际查询数，不能只比较基础改写耗时。

对有段落标注且有索引覆盖的题，A/B 最终 Query 交给同一个混合检索器；C 对多查询结果融合、选择后，取最终 Top-3 计分。重写质量与检索质量分别计分。下游指标使用实验一的 Gold Recall@1、Gold Recall@3 和 MRR@3，并查看 `retrieval_sample_count`（检索计分题数）、`retrieval_error_count`（检索错误数）、`mean_retrieval_ms`（成功检索的平均耗时）和 `mean_query_total_ms`（成功检索样本的平均重写加检索耗时）。

先用 `ollama list` 核对 8B 标签，如需安装可运行 `ollama pull qwen3:8b`。沿用前面的 `$py`，先检查离线评分和报告导出，再用真实模型试跑两道开发题。

```powershell
& $py -X utf8 -B evaluate_rewrite.py --mode demo --split dev --limit 2 --rewrite-only
& $py -X utf8 -B evaluate_rewrite.py --mode ollama --model qwen3:8b --strategies rewrite structured compcqr --split dev --limit 2
```

去掉 `--limit 2` 可跑 102 道项目开发题。固定方法后，可用 `--split test` 跑 205 道项目测试题，或用 `--split all` 汇总项目 307 道题。纯重写评测可直接读取官方测试对话。C 在 `--rewrite-only` 下不执行多查询检索及最佳文档选择，所得 ROUGE 只反映基础组件。

```powershell
& $py -X utf8 -B evaluate_rewrite.py --mode ollama --model qwen3:8b --strategies rewrite structured compcqr --data data/qrecc/source/qrecc-test.json --data-format qrecc-json --split test --rewrite-only
```

官方 JSON 也包含没有历史的首轮，分析时可用逐题记录里的 `history` 单独汇总有历史的样本。若要使用本地小索引诊断官方题的检索表现，把 `--rewrite-only` 换成 `--allow-partial-corpus`。只有带标注且至少一个正例在索引里的题参与检索计分，每道计分题的 Recall 分母仍保留该题的全部标注正例。其余题参与重写评分。运行后通过 `report.json` 的 `metadata.retrieval` 核对索引范围和标注覆盖。

## 输出文件和续跑

- `evaluate.py` 的默认运行目录在 `outputs/runs/`，`evaluate_rewrite.py` 的默认运行目录在 `outputs/rewrite_runs/`。先看 `summary.csv`，再按题目 ID 在 `report.json` 或 `details.csv` 中查 Query、改写来源、排名、计时或错误。`manifest.json` 记录运行签名，`checkpoint.jsonl` 记录已写入的逐题结果。
- 主实验同时生成 `blind_review_reviewer1.csv` 和 `blind_review_reviewer2.csv`。两人独立打分后，再用 `blind_review_key.json` 对应回组别。更多操作见 [问题重写实验说明](问题重写实验说明.md)。
- 首次运行指定 `--output-dir` 时，路径应指向尚未创建的目录。中断后用原目录和相同参数追加 `--resume`。续跑检查数据、配置、源码及模型身份，跳过已记录的题目，包括已记录的失败。已有最终 `report.json` 的运行已完成。另起一轮或换模型时使用新的输出目录。

## C 的具体设置

C 使用五个非空组件时，dense/hybrid 最多组合 325 条查询，BM25 最多使用 31 个无序子集。默认每查询检索 Top-100，跨查询 RRF 常数为 0，模型最多从 5 篇截断候选中选择最佳段落。现有混合检索内部的两路 RRF 常数仍为 60。选择失败保留融合顺序并记录错误。模型、检索器和候选预算与论文不同，应称为 CompCQR 适配实现。参数、流程与复现边界见 [CompCQR 说明](CompCQR说明.md)。

A/B/C 的混合检索内部候选深度统一为 `hybrid_candidate_depth=400`，不随最终 Top-K 或 C 每查询检索深度改变；两路 RRF 仍使用常数 60。C 选择提示的 6,000 字符预算包含指令、问题、同样历史和段落，实际候选数以运行记录为准。
