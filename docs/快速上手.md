# 快速上手

主实验比较 **QReCC 问题重写 A/B**。给定同一道追问和相同的可见历史（最多三轮问答），A 让模型直接生成独立问题，B 让模型先给出结构化结果，校验发现问题时再尝试修复一次。批量评估既对照人工重写，又用最终 Query 进行 **BM25 + `bge-m3` 混合检索**。

## 1. 先在网页上看一题

项目需要 Python 3.10 或更高版本，基础流程只使用 Python 标准库。双击项目根目录的 `start_qrecc_demo.bat`，打开 [重写实验页](http://127.0.0.1:8001/rewrite)。如果打开的是 RAG 首页，点击「进入问题重写 A/B 实验」。

1. 在「QReCC 题目」下拉框选一道题，例如 `1471-2`。当前问题是 *What year did the band form?*，上一轮谈的是 Fleet Foxes。
2. 看「两组看到的对话历史」，点「运行 A/B」，比较两列输出，再展开「查看人工参考重写」。可以检查输出是否把 *the band* 换成 *Fleet Foxes*，并保留询问乐队成立年份的意图。
3. `demo` 用本地规则演示流程。要看 Qwen 的实际输出，先关闭演示窗口，确认 `ollama list` 中有 `qwen3:1.7b` 和 `bge-m3`，再双击 `start_qrecc.bat`，回到重写实验页核对页首的模式和模型。缺少模型时，在 Ollama 启动后执行 `ollama pull qwen3:1.7b` 或 `ollama pull bge-m3`。

想直接启动真实模型的重写页，也可以在项目根目录运行下面这条命令。若之前的网页服务还占用 8001 端口，先关闭它。

首次启动时，网页先打开，混合索引在后台准备。首页会显示「准备索引中」，启动窗口显示向量生成进度，完成后页面自动恢复。后续语料与配置未变时会复用索引。请保持启动窗口打开。

部分段落超过 Ollama 实际提供的向量输入窗口。向量化时允许服务按窗口截断，以避免 HTTP 413；原始 passage、段落 ID、BM25 正文和用于回答的证据仍完整保留。超长段落尾部的信息可能未进入向量，实验记录和索引指纹会保存该输入策略。

```powershell
& 'G:\Anaconda3\python.exe' -X utf8 -B app.py --page rewrite --mode ollama --port 8001
```

## 2. 在命令行跑 A/B 实验

在**项目根目录**打开 PowerShell。以下命令使用这台电脑的 Python 路径。换电脑时，改为实际的 Python 路径，或者在 Python 已加入 PATH 时用 `python`。

```powershell
# 先跑 2 道题，确认能读取数据并生成结果
& 'G:\Anaconda3\python.exe' -X utf8 -B evaluate_rewrite.py --mode demo --limit 2

# 主实验用 8B，先跑 2 道开发题，检查重写与混合检索
& 'G:\Anaconda3\python.exe' -X utf8 -B evaluate_rewrite.py --mode ollama --model qwen3:8b --split dev --limit 2
```

第二条命令需要先安装 `ollama pull qwen3:8b`。默认比较 A（`rewrite`）和 B（`structured`）。去掉 `--limit 2` 可以跑 102 道开发题，固定方法和参数后用 `--split test` 跑 205 道测试题，使用 `--split all` 跑项目全部 307 题。第一次运行混合检索需要建立索引。实验一的三种 Query 策略与实验二的模型对照见 [实验指南](实验指南.md)。

以后要扩大评测范围，可以读取项目里的官方完整测试文件。先限制为 10 条，确认新数据入口可用。

```powershell
& 'G:\Anaconda3\python.exe' -X utf8 -B evaluate_rewrite.py --mode demo --data data/qrecc/source/qrecc-test.json --data-format qrecc-json --split test --limit 10 --rewrite-only
```

用真实模型在官方测试文件上单独测重写质量时，把 `--mode demo` 换成 `--mode ollama --model qwen3:8b`，再去掉 `--limit 10`。完整 QReCC 混合检索需要另接全量语料索引。

## 3. 看运行结果

终端会打印每组的题数、ROUGE-1 F1、错误数、回退数，以及结果目录。默认输出到 `outputs/rewrite_runs/<时间戳>/`。

| 文件 | 先看什么 |
| --- | --- |
| `summary.csv` | 比较 A/B 的重写分数、下游检索指标、耗时、错误和回退次数 |
| `details.csv`、`report.json` | 按题目 ID 对照两组改写、人工参考和检索结果，检查修复或回退记录 |
| `blind_review_reviewer1.csv`、`blind_review_reviewer2.csv` | 独立检查指代是否补对、原意与约束是否保留、补入的信息有没有历史依据 |

ROUGE-1 衡量词面重合。遇到分数与直觉不一致的题，结合对话历史判断改写是否保留原意、能否独立理解。正式报告使用 Ollama 模式的结果，并说明错误和回退情况。更多评测细节见 [问题重写实验说明](问题重写实验说明.md)。

## 4. 体验完整 RAG 或开始读代码

打开 [RAG 问答首页](http://127.0.0.1:8001/)，可以先问 *What is a fat tree topology?*，再追问 *What are its characteristics?*。展开「查看检索过程」，看构造好的 Query 找到了哪些证据、最后的回答引用了哪些来源。离线演示用 BM25 展示证据摘录，Ollama 模式用混合检索找证据后生成回答。

读重写代码时，建议从 [rag/rewriters.py](../rag/rewriters.py) 的 A/B 提示、校验和修复看起，再读 [rag/pipeline.py](../rag/pipeline.py) 的 `rewrite_query()`，最后看 [evaluate_rewrite.py](../evaluate_rewrite.py) 如何逐题运行和保存结果。想继续看检索时，再读 [rag/retrieval.py](../rag/retrieval.py)。
