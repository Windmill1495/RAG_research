# 快速上手

先在网页选一道题，看看 A/B/C 如何根据历史补全追问，再用命令行跑两道题生成报告。项目需要 **Python 3.10 或以上**，离线演示使用标准库。真实模型运行另需 Ollama。

## 1. 打开网页

Windows 上双击项目根目录的 `start_qrecc.bat`，打开 [RAG 首页](http://127.0.0.1:8001/)，再点击「进入问题重写 A/B/C 实验」。也可以从已有服务直接打开 [A/B/C 重写页](http://127.0.0.1:8001/rewrite)。

启动器会查找 Python，并尝试启动本机 Ollama。当前配置的 `qwen3:1.7b` 和 `bge-m3` 都可用时，页面使用本地模型，否则进入离线规则演示。看重写页右上角即可确认实际模式。

如果想直接试离线重写，在**项目根目录**打开 PowerShell，运行下面的命令。若已有网页服务占用 8001，先在旧服务的终端按 `Ctrl+C`，或给新服务换一个端口。

```powershell
$py = 'G:\Anaconda3\python.exe'
& $py -u -X utf8 -B app.py --mode demo --page rewrite --port 8001
```

换电脑时把 `$py` 改为实际的 Python 路径。Python 已加入 PATH 时，可用 `$py = 'python'`。上面的命令直接打开 A/B/C 页，离线对照使用规则重写，适合先检查选题、历史和评分的展示流程。

## 2. 看懂一条重写结果

1. 在「QReCC 题目」中选开发题 **`1471-2`**。当前问题是 *What year did the band form?*，上一轮在谈 Fleet Foxes。
2. 展开「三组看到的对话历史」，再点击「运行 A/B/C」。离线演示中三组都不调用模型，C 只组合可用的规则组件。切到本地模型后，A 直接重写，B 先生成结构化结果，发现校验问题时可修复一次。C 生成问题与假设答案组件，组合多查询检索，并选择最佳段落。页面会记录实际来源、调用次数与修复状态。
3. 打开「查看人工参考重写」。这一题的参考是 *What year did Fleet Foxes form?*。看输出是否补对了 *the band*，并保留询问成立年份的意图。

**ROUGE-1 F1** 衡量改写与参考在词面上的重合程度。C 卡片中的 ROUGE 只评价基础独立改写；完整 C 需查看最终融合、选择后的检索指标。展开「查看 CompCQR 过程」可核查组件、组合查询和文档选择。不同措辞也可能保留同样的含义。使用真实模型时，还可查看 **Gold Recall@1、Gold Recall@3 和 MRR@3**，分别看标注段落在首位、前三位的覆盖，以及首个标注段落排得多靠前。

想试完整问答，可以返回 [RAG 首页](http://127.0.0.1:8001/)，先问 *What is a fat tree topology?*，再追问 *What are its characteristics?*。展开「查看检索过程」，就能看到 Query、证据段落和耗时。

## 3. 用本地模型运行 A/B/C

先启动 Ollama，用 `ollama list` 查看模型。只需下载缺少的标签。

```powershell
ollama list
ollama pull qwen3:1.7b
ollama pull bge-m3
```

体验单题先用默认的 1.7B 即可。可双击 `start_qrecc.bat` 后进入重写页，或在 PowerShell 直接启动。

```powershell
& $py -u -X utf8 -B app.py --mode ollama --page rewrite --rewrite-model qwen3:1.7b --port 8001
```

页首应显示「本地 Ollama」及所用模型。直接打开重写页时，首次需要检索的 A/B/C 对照会准备共享索引。进入 RAG 首页时，页面先打开，索引在后台准备，期间会显示「准备索引中」。启动终端里的 `Embeddings: 已完成数量/总数量` 是实际进度。

首次混合索引需用 `bge-m3` 为 **9,975 个段落**生成向量。保持启动终端打开，直到索引完整保存。相同语料、嵌入权重和相关配置可复用 `.cache/qrecc/index.json`。离线 BM25 使用独立的 `.cache/qrecc/index-bm25.json`。

## 4. 批量试跑两道题

在另一个 PowerShell 窗口进入项目根目录，并设置同一个 `$py`。先用这条命令检查数据读取、重写评分和报告导出。`--rewrite-only` 跳过下游检索。对 C 而言，它也跳过最终文档选择，只评价基础改写，不是完整 C 的成绩。

```powershell
$py = 'G:\Anaconda3\python.exe'
& $py -X utf8 -B evaluate_rewrite.py --mode demo --split dev --strategies rewrite structured compcqr --limit 2 --rewrite-only
```

主实验的正式设置使用 **`qwen3:8b`**。确认 Ollama 中已有 8B 和 `bge-m3`，需要时运行 `ollama pull qwen3:8b`，再做两道开发题的真实模型试跑。脚本默认比较 A（`rewrite`）、B（`structured`）和 C（`compcqr`），并评估各方法最终排名的 Top-3 混合检索效果。C 的完整流程通常有两次组件生成和一次文档选择调用，最多执行 325 条组合查询，先保持 `--limit 2`。

```powershell
& $py -X utf8 -B evaluate_rewrite.py --mode ollama --model qwen3:8b --split dev --strategies rewrite structured compcqr --limit 2
```

去掉 `--limit 2` 可跑 **102 道开发题**。固定方法和参数后，换成 `--split test` 跑 **205 道测试题**。`--split all` 运行项目中的 **307 题**。实验一的 Query 策略比较、实验二的模型规模比较，以及如何用官方 JSON 扩大纯重写评测，见 [实验指南](实验指南.md)。

## 5. 找到报告

终端最后会打印运行目录，默认在 `outputs/rewrite_runs/` 下为每次运行创建一个时间戳目录。

| 文件 | 先看什么 |
| --- | --- |
| `summary.csv` | A/B/C 的题数、平均 ROUGE、适用的检索指标、耗时和错误计数 |
| `details.csv`、`report.json` | 按题目 ID 查看实际改写、人工参考、修复或回退和检索排名 |
| `blind_review_reviewer1.csv`、`blind_review_reviewer2.csv` | 供两位评审检查指代、省略、原意与约束、无依据新增和独立可读性 |
| `blind_review_key.json` | 盲评结束后还原策略组别 |

离线试跑用于验证流程，正式结果从 `ollama` 模式的运行目录读取。评分、覆盖范围与续跑详见 [问题重写实验说明](问题重写实验说明.md)。

C 的组件假设答案只用于检索扩展，不作为最终回答的证据。实现与论文设置的差异、参数解释和代码阅读入口见 [CompCQR 说明](CompCQR说明.md)。
