# 问题重写 A/B 实验说明

## 这次比较什么

给定当前问题和此前最多三轮问答，生成一句保持原意、可以独立理解的英文问题。比如，历史一直在谈某位作家时，*When did she publish her first novel?* 中的 *she* 需要换成对应人名，*first novel* 和问时间的意图也要保留。实验比较最终的重写句子。

| 组别 | 给模型的任务 | 程序处理 |
| --- | --- | --- |
| A · `rewrite` | 直接返回一条独立问题 | 解析 `query`，做基本格式和约束检查 |
| B · `structured` | 同时返回主题、指代对象、独立问题和歧义标记 | 检查草稿及其依据，触发校验问题时允许再修复一次，取最终 `standalone_query` |

两组共用模型、题目和原始可见历史。B 的变化包含结构化提示、额外检查和条件修复，因此结果反映这套流程的整体效果。程序会记录 B 是否修复、调用次数和失败原因。每组的最终 Query 同时送入相同的 **BM25 + `bge-m3` 混合检索**，在有标注且被索引覆盖的题上单独评估下游效果。

## 题目与输入边界

- **当前评测全部 307 题。** [questions.jsonl](../data/qrecc/questions.jsonl) 包含 102 道开发题和 205 道测试题。两组按同一题目顺序逐题比较，共生成 614 条结果。题目来自既有的检索覆盖筛选子集。
- **模型看到什么。** 输入只有当前问题和窗口内的历史。QReCC 的固定参考历史来自此前轮次的人工 `Rewrite` 与已有参考答案。当前轮的人工 `Rewrite` 交给评测层，用来比较输出。
- **后续完整对话集。** 从 [QReCC 官方归档](https://zenodo.org/records/5760304) 取得 `qrecc-training.json` 或 `qrecc-test.json`。`--rewrite-only` 可直接读取官方对话 JSON 评估改写质量。需要同时跑完整下游检索时，要有完整混合索引。做新的正式研究时，按会话隔离开发集与测试集，把已用于设计的会话留作诊断。

## 运行和阅读结果

在项目目录执行。全局默认模型为 `qwen3:1.7b`，主实验显式使用 `qwen3:8b`。运行前用 `ollama list` 检查 `qwen3:8b` 和 `bge-m3` 是否已安装。如已把 Python 加到 PATH，可把命令里的 Python 路径换成 `python`。

```powershell
# 小样本流程检查
& 'G:\Anaconda3\python.exe' -X utf8 -B evaluate_rewrite.py --mode demo --limit 2

# 项目全部 307 题，用 Qwen3-8B 跑 A/B 与混合检索
& 'G:\Anaconda3\python.exe' -X utf8 -B evaluate_rewrite.py --mode ollama --model qwen3:8b --split all

# 用现有官方测试 JSON 检查新数据入口，先限制为 10 题
& 'G:\Anaconda3\python.exe' -X utf8 -B evaluate_rewrite.py --mode demo --data data/qrecc/source/qrecc-test.json --data-format qrecc-json --split test --limit 10 --rewrite-only
```

默认的 307 题可以通过 `--split dev` 或 `--split test` 分开运行。程序默认抽取 30 题导出盲评表，可用 `--review-count` 调整。对官方测试文件批量测重写质量时，把最后一条的 `--mode demo` 换成 `--mode ollama --model qwen3:8b`，并移除 `--limit 10`。如果使用官方训练文件，把数据路径换成训练文件路径，同时使用 `--split train`。传入其他 JSONL 时可显式指定 `--split all`，读取文件中的全部划分。

完整官方文件包含每段对话的第一轮。第一轮没有历史时，两组会直接保留原问题，来源标为 `no_history`，模型调用次数为 0。报告正式结果时，可以按来源把这类题和有历史的追问分别汇总。命令里的 `--limit` 只取文件顺序前缀，适合验证入口。

| 运行文件 | 怎么读 |
| --- | --- |
| `summary.csv` | 比较每组题数、平均 ROUGE-1 Precision/Recall/F1、重写耗时、错误和回退计数。检索部分单列计分题数、Gold Recall@1/@3、MRR@3 和检索错误数 |
| `details.csv`、`report.json` | 对着同一个题目 ID 看 A/B 的历史、原问、改写、人工参考和检索结果。JSON 中可追溯模型调用和修复记录 |
| `blind_review_reviewer1.csv`、`blind_review_reviewer2.csv` | 两名评审独立检查指代和省略、原意与约束、无依据新增、独立可读性。允许等义表达 |
| `blind_review_key.json` | 评审结束后用此表还原组别，统计 A 错 B 对、A 对 B 错、两组都对、两组都错 |
| `manifest.json`、`checkpoint.jsonl` | 保存运行签名与已完成记录。需要续跑时，用同一输出目录和相同参数追加 `--resume` |

ROUGE 看词面重合，语义质量以人工盲评和案例分析为主。脚本分别统计重写和检索的分母，检索失败时仍保留改写质量评分。重写硬失败以空输出记零，启发式回退按实际输出评分并单列。离线 `demo` 用规则重写和 BM25 验证流程。正式对照用 Ollama 模式报告，同时核对重写来源、模型标识与检索后端。

### 网页逐题对照

```powershell
& 'G:\Anaconda3\python.exe' -X utf8 -B app.py --page rewrite --mode ollama --port 8001
```

打开 [重写实验页](http://127.0.0.1:8001/rewrite)，可从全部 307 题中选题。两列结果共用同一份输入，人工参考可展开查看。网页适合观察一个案例，命令行负责批量运行和保存结果。`start_qrecc.bat` 和 `start_qrecc_demo.bat` 从 [RAG 首页](http://127.0.0.1:8001/) 启动。若已有一个服务占用同一端口，可以在已打开的 RAG 网页上点击重写实验链接。

### 以后怎么比不同模型

先用 `ollama list` 核对本机已有模型的完整标签。比较 Qwen2.5 与 Qwen3，或比较同系列不同参数规模时，每个标签单独运行一次。将 `--model qwen3:1.7b` 换成目标标签，其余数据、策略、历史范围和评分参数保持一致。用各自的新输出目录，按题目 ID 和策略配对结果。同一策略跨模型对照，才能把模型因素与 A/B 方法因素分开。网页单题体验可在启动时指定 `--rewrite-model`。

## 每个文件为什么这样写

建议从一条题目的执行路径读起，依次看题目清单、数据适配、A/B 策略、评测脚本、网页。

| 文件 | 职责与设计原因 |
| --- | --- |
| [data/qrecc/questions.jsonl](../data/qrecc/questions.jsonl) | 保存 307 道项目题及其 ID、划分、历史和人工参考。换模型时可以按题目 ID 逐题配对 |
| [rag/rewrite_data.py](../rag/rewrite_data.py) | 读取项目 JSONL 和官方对话 JSON。对官方数据按轮次还原角色历史，使重写任务可以独立于检索标签 |
| [rag/data.py](../rag/data.py) 与 [prepare_qrecc.py](../prepare_qrecc.py) | 前者负责既有项目数据的校验和公开输入，后者准备带段落标签的检索子集。按任务分开数据入口，便于分别控制两种实验的入选条件 |
| [rag/rewriters.py](../rag/rewriters.py) | 集中存放 A/B 提示、输出校验、修复与回退，便于明确比较方法本身的差异 |
| [rag/pipeline.py](../rag/pipeline.py) | 统一清理可见历史并调用重写策略，实验可复用同一历史处理、模型客户端与检索器 |
| [rag/llm.py](../rag/llm.py) 与 [config.json](../config.json) | 前者统一发起 Ollama 请求，后者集中给出默认模型标签和服务地址。命令行覆盖标签后可保持两组请求设置一致 |
| [configs/qrecc.json](../configs/qrecc.json) | 集中设置 QReCC 的语料、索引路径和最近三轮历史等默认值 |
| [evaluate_rewrite.py](../evaluate_rewrite.py) | 汇总重写评分与下游检索结果，供批量对比与人工盲评 |
| [rag/metrics.py](../rag/metrics.py) 与 [rag/run_cache.py](../rag/run_cache.py) | 前者统一文本评分口径，后者校验运行签名和续跑检查点，避免把不同模型或数据的结果拼进同一次运行 |
| [app.py](../app.py) | 为网页提供样本列表和逐题 A/B 对照接口，复用同一套重写逻辑，同时保留已有的问答路由 |
| [web/index.html](../web/index.html)、[web/rewrite.html](../web/rewrite.html)、[web/rewrite.js](../web/rewrite.js)、[web/style.css](../web/style.css) | 原主页负责 RAG 问答，重写页展示单题两列结果，脚本负责请求与更新页面，共享样式用于统一显示 |
| [tests/](../tests/) | 从数据读取、重写逻辑和网页入口分别验证行为，也用来检查原有功能是否受到影响 |

如果只想先弄清楚 A 和 B 的算法差别，从 `rag/rewriters.py` 的两个提示词和策略分支开始。想理解为什么某个分数变化，再对照报告里的最终输出、修复记录和人工参考。
